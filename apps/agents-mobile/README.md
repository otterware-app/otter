# Otter Agents for iPhone (Expo)

Otter Agents runs core in the
app (`@otter/mobile`'s `startMobileCore`, started from `index.ts` before the screens), the frame
(three tabs, each its own stack, under the ask bar and tab row of `src/frame/`), the components
at `/gallery` and a development self-test at `/self-test`.

## Running

```sh
pnpm dev:mobile:agents                     # prebuild, build the dev client, run it in the simulator, start Metro
pnpm dev:mobile:agents:fake                # the same over core's fake: a made-up account, scripted agents and chats, no network
pnpm --filter @otter/agents-mobile ios --device <udid>   # on a given simulator or iPhone
pnpm --filter @otter/agents-mobile dev     # Metro alone, for a dev client already installed
```

The fake is `EXPO_PUBLIC_OTTER_DATA=fake`, read when Metro bundles: start Metro with it
(`EXPO_PUBLIC_OTTER_DATA=fake pnpm --filter @otter/agents-mobile dev`) to run an installed dev
client over the fake. Its files, database, storage and Keychain service are its own, apart from
real data. `EXPO_PUBLIC_OTTER_RELAY_URL` points the app at another relay (a local one:
`http://localhost:8787`).

`EXPO_PUBLIC_OTTER_AGENTS` makes the agents real, over the fake's account: it connects them to
this checkout's local gateways (`pnpm agents-server`, docs/development.md#agent-gateways), whose
address and key `pnpm -s agents-server json` prints. With the gateways up:

```sh
EXPO_PUBLIC_OTTER_AGENTS="$(pnpm -s agents-server json)" pnpm dev:mobile:agents:fake
```

The fake's first OpenClaw agent (Studio) and first Hermes agent (brokk) connect to them at each
start; the rest is made up. Development builds only.

Metro listens on port 8097. `ios/` is generated by `expo prebuild` from `app.config.ts` and not
committed: change the config (or a config plugin), never `ios/`, and run
`pnpm --filter @otter/agents-mobile prebuild --clean` to start it over. Builds are
`dev.otterware.agents.dev`; `OTTER_APP_VARIANT=production` makes them `dev.otterware.agents`.
The project signs with team 838JVGY7W4.

### A dev client on a fresh simulator

An installed development build opens on the running Metro with the dev launcher's link:

```sh
agent-device open dev.otterware.agents.dev "dev.otterware.agents.dev://expo-development-client/?url=http%3A%2F%2Flocalhost%3A8097"
```

(by hand: `xcrun simctl openurl <udid> "<that link>"`). iOS asks "Open in “Otter
Agents”?" (Open), then the dev menu shows its introduction once (Continue). Then, once per
simulator, turn off the dev menu's **Tools button** (dev menu: ⌃⌘Z or the gear button; at the
bottom of Tools): it floats over the header's trailing buttons. Afterwards the app reopens on the
same Metro by itself, and any route opens by link: `dev.otterware.agents.dev://settings/chat`,
`…://gallery`, `…://self-test` (each link asks "Open in…" again).

## The self-test

`/self-test` (open `dev.otterware.agents.dev://self-test`; in development builds and any build
over the fake, never in a release) runs what core needs of Hermes and of the phone (Web Crypto, streams,
`TextDecoder`, SQLite's FTS5 and JSON1, the Keychain, files…) and, over the fake, a round trip
through `@otter/client`: the agents, the chats, and a message to a scripted agent followed to the
end of its reply, with how long the JavaScript thread was held meanwhile (a chat it deletes
after). A known gap (Blob from bytes) shows without failing it.

## The fake

Over the fake (`packages/core/src/fake`): an Otter account, four agents (brokk and rata on Hermes,
Studio on OpenClaw, varys), chats on every shelf, scheduled tasks with runs, and a scripted agent:
a message with "ask" or "plan" gets a question, "send", "run" or "approve" an approval, "fail" a
failure, "delegate" a wait on a subagent, "take your time" a slow reply (to try steering, the queue and Stop). It has no Talk, no
live browser and no forks. It has sessions "On your agents", files of every kind (from "Get ready for
Thursday's planning"), model options on brokk, scheduled tasks that fail to load (rata) or are
read-only (varys), and an Otter account that signs out and in and lists other devices.

## Writing screens

A screen's route file re-exports it from `src/chats/`, `src/chat/`, `src/scheduled/`,
`src/settings/` or `src/account/`. The layouts and system links live in `src/app/`, with
navigation and the tab bars in `src/frame/`.

| Route                                                               | File                                                                              | Shown as                   |
| ------------------------------------------------------------------- | --------------------------------------------------------------------------------- | -------------------------- |
| `/`                                                                 | `chats/chats-screen.tsx`                                                          | the Chats tab              |
| `/sessions`                                                         | `chats/sessions-sheet.tsx`                                                        | sheet                      |
| `/agents/[id]`                                                      | `chat/chat-screen.tsx`                                                            | pushed                     |
| `/agents/[id]/file?path=`                                           | `chat/file-screen.tsx`                                                            | pushed                     |
| `/agents/[id]/details`                                              | `chat/details-sheet.tsx`                                                          | sheet, half and full       |
| `/agents/[id]/model`                                                | `chat/model-sheet.tsx`                                                            | sheet                      |
| `/agents/[id]/queue`                                                | `chat/queue-sheet.tsx`                                                            | sheet, 65 % and full       |
| `/agents/[id]/browser`, `/agents/[id]/talk`                         | `chat/browser-screen.tsx`, `talk-screen.tsx`                                      | full-screen cover          |
| `/new?mail=<json>`                                                  | `chat/new-from-mail.tsx`                                                          | pushed (Otter Mail's link) |
| `/scheduled`                                                        | `scheduled/scheduled-screen.tsx`                                                  | the Scheduled tab          |
| `/scheduled/[id]`                                                   | `scheduled/task-screen.tsx`                                                       | pushed                     |
| `/scheduled/new`, `/scheduled/[id]/edit`                            | `scheduled/task-editor.tsx`                                                       | sheet                      |
| `/settings`                                                         | `settings/settings-screen.tsx`                                                    | the Settings tab           |
| `/settings/agents`, `/settings/agents/new`, `/settings/agents/[id]` | `settings/agents-screen.tsx`, `add-agent.tsx`, `agent-page.tsx`                   | pushed                     |
| `/settings/chat`, `/settings/notifications`, `/settings/licenses`   | `settings/chat-settings.tsx`, `notifications-settings.tsx`, `licenses-screen.tsx` | pushed                     |
| `/settings/otter`                                                   | `account/account-screen.tsx`                                                      | pushed                     |
| `/welcome`                                                          | `account/welcome-screen.tsx`                                                      | alone, while signed out    |

- **Going places**: `router.push` / `router.navigate` / `<Link href>` with the typed paths above
  (`{ pathname: "/agents/[id]", params: { id } }`). `openChat(id)` and `useAsk()` (New chat) are
  in `src/frame/navigation.ts`. Whether a route pushes or presents is set in its tab's
  `_layout.tsx` (`TabStack`'s `presented`); a screen doesn't choose.
- **Header**: from inside the screen. `<Stack.Screen options={{ title }} />` for the title and
  options (a screen is untitled until it sets one, never named after its file; a first screen
  with none, as Chats, leaves it empty); `<Stack.Toolbar placement="right">` (or `"left"`) with `Stack.Toolbar.Button icon="…"`,
  `Stack.Toolbar.View` for anything drawn, and `Stack.Toolbar.Menu` holding
  `Stack.Toolbar.MenuAction`s (`icon`, `destructive`, `onPress`). See `chats/chats-screen.tsx`
  and the gallery. `<Stack.SearchBar placeholder onChangeText />` puts the system's search field
  at the bottom of the screen (iOS 27), where a tab's first screen has its bars: there, search as
  the Swift app does, from a header button.
- **The bars**: they belong to each tab's first screen and leave with it when a screen is
  pushed. A first screen that wants them gone for a while (selecting) calls `useHideBars(true)`
  (`src/frame/frame-store.ts`); its scroll view adds `useBottomBarInset()`
  (`src/frame/tab-root.tsx`) to its bottom `contentInset` and `scrollIndicatorInsets`.
- **Sheets**: a sheet's screen returns `Sheet` (`@otter/ui-native/components/sheet`: title,
  Cancel, Done) as its outermost element, never wrapped in a `View`: react-native-screens sizes a
  form sheet's scroll view by the view before it, and `Sheet` gives it exactly a header and the
  scroll view (`scrolls={false}` for a list that scrolls itself). A form sheet puts that scroll
  view right under the header, with no inset of its own: `Sheet` pads its body, and a list that
  scrolls itself pads its own top. `cancelLabel` names the × ("Close" with nothing to discard),
  `tint` colors the × and fills the ✓ (an editor's, in the app's color), `trailing` stands in for
  the ✓ (a "Show all" toggle: a `Button`, `glass` or `glass-prominent` with `tint`). The detents
  are the layout's (`sheet([0.5, 1])` in `src/frame/stack-options.ts`, grabber always shown), and
  which routes present is the tab layout's `presented`: a link, a notification or `openChat`
  closes what's up first (`closeSheets`). Close with `router.back()`. A sheet with unsaved
  changes refuses to go without asking (SwiftUI's `interactiveDismissDisabled`):
  `usePreventRemove(changed, ({ repeat }) => …)` from expo-router catches Cancel and a swipe down.
  Clear `changed` before replaying the dismissal with `repeat()` or disabling prevention after a
  save (`scheduled/task-editor.tsx`). A full-screen cover (`browser`, `talk`) has no header and
  pads its top by `useSafeAreaInsets().top`.
- **Drawing**: `StyleSheet` or inline styles over `useTheme()`'s tokens (`theme.colors.*`,
  `theme.radius.*`, `theme.space[n]`), `alpha(color, opacity)` for a token at an opacity. All
  text is `Text` (`size`, `weight`, `color` as tokens); `typeStyle(theme, step, weight)` for
  text drawn by something else (a header, an input). Icons are SF Symbols through `Icon`.
- **Components** (`@otter/ui-native/components/*`, all at `/gallery`): `Button`, `IconButton`,
  `Badge`, `BadgeDot`, `Avatar`, `Chip`, `Switch`, `EmptyState`, `Alert` (a banner, not a
  dialog), `Toast`, `Spinner`, `Separator`, `Glass`, `ListRow` and `SwipeRow` for list rows,
  `SettingsPage`, `SettingsSection`, `SettingsRow`, `SettingsSwitchRow`, `SettingsButton` for
  settings, `Sheet`.
- **Lists**: `FlashList` (`@shopify/flash-list`), as the chats list. FlashList 2 keeps the
  visible row in place as items change (`maintainVisibleContentPosition`, on by default), which
  scrolls a header away when the items are replaced (search results under a search field): turn
  it off there (`maintainVisibleContentPosition={{ disabled: true }}`). Touch and hold a row for a
  preview and a menu: `<Link href asChild>` holding `<Link.Trigger>` (the row),
  `<Link.Preview style={{ backgroundColor: theme.colors.canvas }} />` (without it the preview is
  transparent) and `<Link.Menu>` with `<Link.MenuAction icon onPress>`s; a tap navigates by
  itself. Wrap the Link in `HeldRow` (`src/frame/held-row.tsx`, with `open` and the menu's
  entries as `actions`): Link's native view has no size, and iOS leaves everything inside one out
  of the accessibility tree, so without it VoiceOver and UI tests can't reach the row. Swipes are
  `SwipeRow`: one action a side runs on a pull, several (an array) open on their buttons and run
  the first on a full swipe, as SwiftUI's `swipeActions`.
- **Confirmations**: React Native's `Alert.alert(title, message, buttons)` (`style:
"destructive"`, `"cancel"`) for a dialog, `ActionSheetIOS.showActionSheetWithOptions` for a
  sheet of choices (`destructiveButtonIndex`, `cancelButtonIndex`). Both in the gallery.
- **Haptics**: `haptics.tap()` / `haptics.impact()` from `@otter/ui-native/haptics` (the
  simulator plays nothing).
- **The keyboard**: the transcript uses `KeyboardChatScrollView` and dismisses the keyboard
  interactively. The footer follows the keyboard and contributes its measured height to the
  transcript's bottom padding. The attachment tray takes the height of its actions. While
  switching between the two, the footer only moves by the part of the keyboard above the tray.
- **Logic**: everything that isn't drawing is `@otter/client` (`agentApi`, `useChats`, the
  composer, the scheduled editor…; `tmp/parity/otter-agents-map.md` maps each screen to it). A
  screen needing logic that isn't there asks for it rather than writing it in the app.

## Sharing Metro

Several people (or agents) can run this development build on their own simulators against one
Metro. So:

- The bundle must build at all times: write a file whole, never leave one half-edited, and run
  `pnpm --filter @otter/agents-mobile typecheck` before saving a risky change.
- A red screen from a file outside your area is someone else's edit in flight: wait and reload,
  never fix their file.
- Nobody restarts Metro or adds a native dependency (which needs a new build for everyone)
  without saying so first.
- Format only your own files: `pnpm exec vp fmt <paths>`.
- Someone else's save can reload your app: an edit to a module that loads before the screens
  (`@otter/client`, core) is a full reload, back to the route you were on as the stack's only
  screen. Open the place again by link.
